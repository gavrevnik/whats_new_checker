# Что дальше?

Локальная библиотека фильмов и музыкальных альбомов с бэклогом, оценкой просмотренного/прослушанного и персональными рекомендациями. Активные данные хранятся в SQLite, интерфейс работает на `127.0.0.1`. Фильмы обновляются через TMDB, OMDb и Kinopoisk API Unofficial, альбомы и исполнители — через публичный read-only MusicBrainz Web Service API v2, а количество прослушиваний — через ListenBrainz Popularity API.

Однокликовый переключатель-плашка «Фильмы / Музыка» доступен в бэклоге, просмотренном и персонах. Общий слой `content_items` хранит статус и реакцию, а таблицы `movies` и `albums` разделяют данные провайдеров.

## Запуск

Один раз подготовьте локальное окружение для LLM-рекомендаций:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
codex login status
```

Последняя команда должна вывести `Logged in using ChatGPT`. Если авторизации ещё нет, выполните `codex login` и завершите вход через браузер.

После этого на macOS откройте двойным кликом `Whats New Checker.app` или выполните:

```bash
python3 app/server.py --open-browser
```

Адрес приложения: `http://127.0.0.1:8765`.

`.app` запускает сервер как отдельный фоновый процесс и при каждом повторном клике открывает новую вкладку с localhost. Если после обновления кода на порту осталась предыдущая версия сервера, launcher проверяет `/api/health`, безопасно перезапускает только процесс `app/server.py` этого репозитория и пишет диагностический журнал в `.runtime/server.log`.

Основное приложение использует стандартную библиотеку Python 3. Для LLM-вызова официальный Codex SDK установлен из `requirements.txt` в локальную `.venv`, которая не попадает в Git.

## Интерфейс

### Бэклог

Верхние плашки меняют фильмы на музыкальные альбомы одним нажатием. Для альбомов таблица показывает небольшую обложку, название с исполнителем второй строкой, первый выпуск, количество песен, тип, жанры, общее количество прослушиваний ListenBrainz и ссылку поиска альбома в YouTube Music. Кнопки реакции сразу переносят альбом в прослушанное, корзина работает обратимо. Добавлять фильмы и альбомы можно только из бэклога.

Таблица показывает небольшой постер, русское и оригинальное название, дату выхода, режиссёра в формате `русское имя (original name)`, объединённую оценку `IMDb / КП`, страны, жанры, ключевых персон и колонку `Link` со ссылками IMDb/КП. Если рейтинга Кинопоиска нет, значение выглядит как `7 / —`. TMDB ID убран из таблицы и остаётся в подробной карточке. Ключевые поля сортируются нажатием на заголовок. Карточка открывается кликом по названию фильма. Кнопки «Нравится» и «Не понравилось» сразу переносят фильм в соответствующую колонку раздела «Просмотрено», а значок корзины выполняет обратимое удаление. Длинные списки ключевых персон сокращаются до первой персоны и пометки «и др.», но в карточке доступны полностью.

«Актуализировать из TMDB» выбирает карточки без IMDb/Кинопоиск rating, режиссёра или локального постера. Если отсутствует IMDb или режиссёр, выполняется полное TMDB-обогащение и перезаписываются все связанные с TMDB поля; Kinopoisk при этом вызывается только при отсутствующем КП-рейтинге. Если не хватает только КП-рейтинга, вызывается только Kinopoisk API. Если потерян только локальный файл постера, он повторно загружается с TMDB Images без обновления остальных данных. Полностью заполненные карточки не создают внешних запросов.

В открытой карточке отдельная кнопка «Актуализировать из TMDB» применяет ту же логику только к выбранному фильму. В форме добавления эта кнопка выполняет полное первичное заполнение: TMDB нормализует названия, сведения и поле `Link` со ссылками TMDB/КП, сохраняет `poster_path`, загружает постер `w500`, а ниже показывает рейтинги IMDb/КП, актёров, ключевых персон и описание. TMDB ID и заметки в форме не показываются. Кнопка «Очистить» полностью сбрасывает ручной ввод и найденные данные, оставляя модалку открытой. «Добавить в бэклог» сохраняет фильм в очередь, а кнопки «Нравится» и «Не понравилось» сразу помещают его в соответствующий раздел просмотренного. Если после поиска изменить название или год и нажать актуализацию повторно, приложение выполняет новый поиск по изменённому полю, не используя ID предыдущего результата.

Форма альбома аналогично умеет найти и нормализовать запись по названию, исполнителю, году или MusicBrainz ID. В полной карточке доступны обложка, исполнители, первый выпуск, количество песен, типы релиза, жанры и теги, количество прослушиваний ListenBrainz, страна, лейбл, каталожный номер, штрихкод, формат носителя, статус конкретного издания и трек-лист. Альбом хранится как MusicBrainz `release-group`, а сведения конкретного издания берутся из выбранного официального `release`. Кнопка актуализации выбирает альбомы без исполнителя, локальной обложки или количества прослушиваний и для каждого выбранного альбома заново загружает полную карточку MusicBrainz/Cover Art Archive; ListenBrainz остаётся одним batch-запросом. Рейтинг MusicBrainz не используется и не хранится.

Кнопка «Порекомендовать фильмы» открывает единую модалку с двумя режимами. Чтобы не потерять введённый запрос или результат случайным кликом, эта модалка не закрывается нажатием на фон или клавишей Escape — закрыть её можно крестиком. В режиме LLM доступны минимальные рейтинги IMDb и Кинопоиска, диапазон лет, минимальная длительность, максимальное количество рекомендаций и свободный запрос. Каждое формальное условие можно отключить галочкой. IMDb по умолчанию ограничен значением 7, Кинопоиск также имеет значение 7, но изначально выключен, а максимальное количество рекомендаций равно 5. Условия передаются модели в системных инструкциях; после TMDB/OMDb/КП они проверяются повторно. Для Кинопоиска постпроверка мягкая: известная оценка ниже порога исключает фильм, но отсутствие КП-оценки не скрывает рекомендацию и отображается пустым значением. Перед отправкой приложение автоматически добавляет в системный контекст случайную выборку понравившихся фильмов, любимых актёров и режиссёров как мягкий сигнал, а также активный бэклог как список исключений. Размер случайной выборки задаётся в модалке и по умолчанию равен 30. Колонки таблицы рекомендаций сортируются в обоих режимах.

Codex возвращает строго структурированный JSON: русское и оригинальное название, год и персональный комментарий. Сервер разбирает его, находит каждый фильм в TMDB, дополняет карточку сведениями TMDB/OMDb/Кинопоиска, повторно проверяет включённые фильтры и исключает дубли. В режиме API TMDB используются фильтры по актёрам, режиссёрам, IMDb/КП, голосам, диапазону лет, длительности и жанрам, а поле «Макс. фильмов» ограничивает размер результата. Верхняя граница года применяется до загрузки подробных карточек. Фильтр Кинопоиска по умолчанию выключен. Английские и русские названия исключаемых жанров нормализуются, поэтому `Animation, Documentary` исключает в том числе локализованные жанры «мультфильм», «анимация» и «документальный». Оба режима показывают одну таблицу со странами и объединённым рейтингом в фиксированной прокручиваемой области. Название открывает подробную карточку, кнопки «В бэклог», «Нравится» и «Не нравится» сохраняют фильм, а серая кнопка «Убрать» удаляет строку только из текущей выдачи. В API-режиме колонка «Заметка» скрыта. Во время API-поиска индикатор показывает число обработанных выбранных персон и процент.

Для музыки та же модалка предлагает режимы LLM и MusicBrainz API. LLM получает случайную выборку понравившихся альбомов, любимых исполнителей, текущий бэклог, диапазон лет и свободный запрос; структурированный результат независимо уточняется через MusicBrainz. Формальные фильтры можно отключать галочками. API-режим запрашивает у MusicBrainz до 100 release groups на каждого выбранного исполнителя, применяет год, типы, дедупликацию и общий рейтинг кандидатов, после чего загружает полные карточки только для первых `Макс. альбомов`. По умолчанию исключены Compilation, Live, Remix, Soundtrack и DJ-mix. Поэтому значение 20 ограничивает дорогую детализацию и ListenBrainz двадцатью альбомами, но не discovery-ответ каждого исполнителя. Прогресс отдельно показывает поиск по исполнителям, загрузку карточек MusicBrainz, обложек Cover Art Archive и статистики ListenBrainz; ошибки источников появляются в панели предупреждений сразу во время обработки. Выпадающие списки исполнителей, актёров и режиссёров содержат локальный поиск по имени, расширяются по ширине и высоте вместе с модалкой и закрываются кликом за их пределами или клавишей Escape. Без прокрутки показывается до 15 персон, последующие записи прокручиваются внутри списка. В любой карточке альбома под обложкой есть ссылка поиска в YouTube Music, составленная из названия, года и исполнителя.

TMDB является обязательным источником для создания полной карточки: его ошибка показывается пользователю, а соответствующий фильм не добавляется в результаты. Кинопоиск — вспомогательный источник. При исчерпании лимита или другой ошибке Kinopoisk API карточка всё равно создаётся по данным TMDB/OMDb, а интерфейс показывает предупреждение и оставляет КП-рейтинг и ссылку пустыми.

### Просмотрено

Фильмы разделены на три колонки:

- «Оценить» — реакция ещё не указана;
- «Понравилось»;
- «Не понравилось».

Повторное нажатие текущей реакции снимает её и возвращает карточку в «Оценить». Любую карточку можно вернуть в бэклог. Карточки показывают русское и оригинальное название и постер справа; клик открывает подробные данные. Звёздочка независимо добавляет фильм в избранное и не меняет реакцию, статус или другие атрибуты.

Для музыки используются те же три колонки и механика реакций. Справа в карточке прослушанного альбома показывается его обложка. Избранное для альбомов намеренно не реализовано; звезда остаётся только у фильмов. Кнопки добавления на вкладке «Просмотрено» нет ни для одного типа контента.

### Избранное

Отдельная вкладка показывает фильмы, отмеченные звёздочкой. Карточка открывает полную информацию, а повторное нажатие звезды убирает фильм только из избранного. Маркер сохраняется независимо от перемещений фильма между бэклогом и просмотренным.

### Персоны

Две таблицы содержат любимых режиссёров и актёров: русское и оригинальное имя, TMDB ID. Все колонки сортируются нажатием на заголовок; по умолчанию актёры и режиссёры отсортированы по русскому имени, исполнители — по имени MusicBrainz. Персону можно добавить вручную или сначала найти и нормализовать через TMDB прямо в форме добавления; первоначально введённые значения сохраняются как `Raw`. Клик по строке открывает карточку, из которой можно актуализировать только выбранную персону. Общая кнопка «Актуализировать из TMDB» сверяет все имена и ID с англоязычным поиском TMDB, учитывает роль и популярность кандидата, сохраняет русскую локализацию и исправляет ошибочные legacy ID. Значок корзины скрывает выбранную роль персоны из активного списка.

В режиме «Музыка» здесь показываются исполнители и группы с типом, страной и MusicBrainz ID. Их можно добавить, найти, точечно или массово актуализировать и обратимо переместить в корзину.

### Корзина

Фильмы, альбомы, персоны и исполнители показываются в отдельных таблицах и восстанавливаются одной кнопкой. Обычное перемещение в корзину мягкое: основные записи и связи не уничтожаются, а содержимое учитывается при дедупликации рекомендаций. Кнопка «Очистить корзину» после подтверждения безвозвратно удаляет все объекты из SQLite и удаляет их локальные постеры и обложки из `data/artwork`, если эти файлы больше не используются другими записями.

## SQLite

Активная база: `data/library.sqlite3`. Описание таблиц и `awards_json`: `data/SCHEMA.md`.

SQLite хранит URL источника и относительный путь к локальному файлу обложки/постера. Сами JPEG находятся в `data/artwork/albums/` и `data/artwork/movies/`; весь `data/artwork/` исключён из Git. При отсутствии файла локальный HTTP endpoint повторно загружает его из Cover Art Archive или TMDB Images и обновляет путь в базе.

Полностью пересобрать локальный кэш без обращений к платным API можно командой `python3 scripts/cache_artwork.py`.

Главные таблицы:

- `content_types`, `content_items`, `movies`, `albums` (включая `raw_json` с первоначальным вводом);
- `people`, `interest_roles`, `movie_people` (включая `raw_json`, метаданные и время последней сверки персон);
- `music_artists`, `album_artists` — исполнители MusicBrainz и связи с альбомами;
- `genres`, `movie_genres`;
- `content_aliases`;
- `trash_entries` — маркеры обратимого удаления со снимком названия для экрана корзины.
- `favorite_movies` — независимые отметки избранных фильмов.

Первичная SQLite-база построена из сохранённых CSV:

```bash
python3 scripts/migrate_csv_to_sqlite.py --force
```

`--force` полностью пересоздаёт активную БД из `legacy/csv/` и удаляет изменения, сделанные после миграции.

Первичное наполнение музыки использует список из `legacy/csv/interests.csv`, скопированный в `data/music_seed_artists.json`, поэтому приложение во время работы не зависит от `legacy/`. Скрипт находит 46 исполнителей и только полноценные альбомы выбранного года: `primary-type = Album` и пустой список `secondary-types` (без Live, Remix, Compilation, Soundtrack и других специальных версий). Он делает реальные запросы с лимитом 1 запрос/с и изменяет выбранную базу, поэтому требует явного подтверждения:

```bash
python3 scripts/bootstrap_music.py --database data/library.sqlite3 --year-from 2026 --year-to 2026 --archive-out-of-scope --apply
```

Без `--apply` команда ничего не меняет. `--archive-out-of-scope` обратимо перемещает ранее загруженные альбомы других лет и специальных типов в корзину. Для безопасной проверки укажите путь к временной базе.

## MusicBrainz

Ключ и OAuth не нужны. Все обращения передают `User-Agent: WhatsNewChecker/2.0 (gavrevns@gmail.com)` и проходят через общий ограничитель не чаще одного запроса в 1,05 секунды. Временные ответы 429/503 и сетевые сбои повторяются ограниченное число раз; массовые операции продолжают работу с остальными записями и возвращают предупреждение в интерфейс.

Вместе с карточкой release group приложение проверяет Cover Art Archive. При наличии фронтальной обложки в SQLite сохраняются URL `https://coverartarchive.org/release-group/{release_group_mbid}/front-500` и относительный путь к локальному JPEG. Если фронтальной обложки нет или CAA отвечает 404, сохраняется пустое поле. Сетевая ошибка CAA показывается предупреждением и при обновлении не стирает уже известную обложку. Документация: [Web Service API](https://musicbrainz.org/doc/MusicBrainz_API), [rate limiting](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting), [release groups](https://musicbrainz.org/doc/Release_Group), [Cover Art Archive API](https://musicbrainz.org/doc/Cover_Art_Archive/API).

ListenBrainz вызывается через `POST /1/popularity/release-group`. Идентификаторы разбиваются на пачки до 10 записей, каждый запрос выполняется только один раз с таймаутом 15 секунд. В рекомендациях сбой одной пачки не скрывает альбомы: у соответствующих карточек остаётся пустое количество прослушиваний, предупреждение сразу появляется в интерфейсе, а обработка продолжается. В SQLite сохраняются `total_listen_count` и время успешной проверки; `null` означает, что ListenBrainz пока не располагает данными. После изменения Popularity API в июле 2026 приложение поддерживает заголовок `Authorization: Token ...` из `LISTENBRAINZ_USER_TOKEN`; без токена сохраняется совместимый публичный вызов, а HTTP 401 превращается в понятное предупреждение. Массовая музыкальная актуализация касается только альбомов без локальной обложки, исполнителя или количества прослушиваний; для каждой выбранной карточки заново загружается полный набор MusicBrainz-данных. Документация: [ListenBrainz Popularity API](https://listenbrainz.readthedocs.io/en/latest/users/api/popularity.html).

## API-ключи

Для локального запуска через `.app` скопируйте безопасный шаблон:

```bash
cp SECRETS.example SECRETS
```

Заполните локальный файл `SECRETS`:

```python
TMDB_API_KEY = "..."
OMDB_API_KEY = "..."
KINOPOISK_API_KEY = "..."
LISTENBRAINZ_USER_TOKEN = "..."  # токен из listenbrainz.org/settings
CODEX_RECOMMENDATION_MODEL = "gpt-5.6-terra"
```

`SECRETS` добавлен в `.gitignore`; в Git включается только `SECRETS.example` с пустыми значениями. Приложение читает файл без выполнения его как Python-кода.

Переменные окружения имеют приоритет над `SECRETS`:

```bash
export TMDB_API_KEY="ваш_tmdb_ключ"
export OMDB_API_KEY="ваш_omdb_ключ"
export KINOPOISK_API_KEY="ваш_kinopoisk_ключ"
export LISTENBRAINZ_USER_TOKEN="ваш_listenbrainz_token"
python3 app/server.py --open-browser
```

Не храните реальные ключи в notebook, исходном коде или отслеживаемых конфигурационных файлах. Если ключ уже попадал в Git или был опубликован, одного добавления в `.gitignore` недостаточно — ключ необходимо перевыпустить.

TMDB не предоставляет структурированные награды кинофестивалей. Поле `awards_json` не затирается пустым ответом и допускает подключение будущего источника Cannes/Berlinale/Venice без миграции схемы.

## Codex SDK и подписка ChatGPT

LLM-рекомендации запускаются через официальный `openai-codex` в изолированном временном каталоге, с read-only sandbox и запретом подтверждений. SDK использует локальную авторизацию Codex, общую для CLI и IDE extension. При входе через ChatGPT расходуется доступ, включённый в план ChatGPT; `OPENAI_API_KEY` приложению не нужен. Обычный OpenAI Platform API имеет отдельный usage-based биллинг и в этой функции не используется. Ответ ограничен JSON Schema из `app/movie_recommendations.schema.json` или `app/album_recommendations.schema.json`; затем приложение выполняет независимое обогащение через TMDB/OMDb/Кинопоиск либо MusicBrainz.

Модель по умолчанию — `gpt-5.6-terra`. Её можно изменить через `CODEX_RECOMMENDATION_MODEL` в локальном `SECRETS` или одноимённую переменную окружения.

## Legacy

Старый notebook, TMDB/Spotify Python-код, Markdown-списки, исходные CSV и старый генератор миграции сохранены в `legacy/` и не изменяются новой интеграцией. Секреты в notebook заменены безопасными маркерами; активное приложение legacy-файлы не читает.
