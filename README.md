# whatsNew

Локальная библиотека фильмов и музыкальных альбомов с бэклогом, оценкой просмотренного/прослушанного и персональными рекомендациями. Активные данные хранятся в SQLite, интерфейс работает на `127.0.0.1`. Фильмы обновляются через TMDB, OMDb и Kinopoisk API Unofficial, альбомы и исполнители — через публичный read-only MusicBrainz Web Service API v2, фотографии исполнителей — через fanart.tv, а количество прослушиваний — через ListenBrainz Popularity API.

Однокликовый переключатель-плашка «Фильмы / Музыка» доступен в бэклоге, просмотренном, персонах, избранном и корзине; «Избранное» в левой навигации расположено сразу после «Персон». Экраны библиотеки не дублируют название текущей вкладки отдельной верхней шапкой. В бэклоге и персонах переключатель со счётчиком расположен слева, а действия и поиск собраны справа. Бэклог сразу показывает два независимых входа в рекомендации: зелёный CTA «✦ Подобрать похожее» для LLM и «↻ Новое от авторов» для API. Второстепенные действия «＋ Добавить вручную» и «⟳ Обновить» скрыты в меню `…`; аналогичное меню используется на вкладке персон. На вкладке «Просмотрено» переключатель и поиск находятся внутри общей рамки тулбара без изменения их расположения. Прозрачный логотип отображается крупным знаком над названием WhatsNew в центрированном винтажном бренд-блоке боковой панели и как favicon вкладки браузера. Общий слой `content_items` хранит статус и реакцию, а таблицы `movies` и `albums` разделяют данные провайдеров.

## Запуск

Один раз подготовьте локальное окружение для LLM-рекомендаций:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
codex login status
```

Последняя команда должна вывести `Logged in using ChatGPT`. Если авторизации ещё нет, выполните `codex login` и завершите вход через браузер.

После этого на macOS откройте двойным кликом `Whats New Checker.app` или выполните:

```bash
python3 app/server.py --open-browser
```

Адрес приложения: `http://127.0.0.1:8765`.

`.app` запускает сервер как отдельный фоновый процесс и при каждом повторном клике открывает новую вкладку с localhost. Если после обновления кода на порту осталась предыдущая версия сервера, launcher проверяет `/api/health`, безопасно перезапускает только процесс `app/server.py` этого репозитория и пишет диагностический журнал в `.runtime/server.log`.

Основное приложение использует стандартную библиотеку Python 3. Для LLM-вызова официальный Codex SDK установлен из `requirements.txt` в локальную `.venv`, которая не попадает в Git.

## Интерфейс

### Бэклог

Переключатель в левом краю тулбара меняет фильмы на музыкальные альбомы одним нажатием. Для альбомов таблица показывает небольшую обложку, название с исполнителем второй строкой, первый выпуск, количество песен, общее количество прослушиваний ListenBrainz, ссылку поиска альбома в YouTube Music и дату добавления в локальную базу. Тип и жанры остаются в подробной карточке. Кнопки реакции сразу переносят альбом в прослушанное, корзина работает обратимо. Добавлять фильмы и альбомы можно только из бэклога.

Таблица показывает небольшой постер, русское и оригинальное название, дату выхода, режиссёра в формате `русское имя (original name)`, объединённую оценку `IMDb / КП`, страны, ключевых персон и дату добавления в локальную базу. Колонка «Добавлено» расположена непосредственно перед колонкой CalendarCheck и сортируется по дате; первый клик показывает новые записи сверху. Отдельной колонки `Link` нет: ссылки КП и RuTr расположены прямо под парой названий фильма. Жанры остаются в подробной карточке. RuTr ведёт на поиск RuTracker по русскому названию и году фильма. Если рейтинга Кинопоиска нет, значение выглядит как `7 / —`. TMDB ID убран из таблицы и остаётся в подробной карточке. Ключевые поля сортируются нажатием на заголовок. В компактной колонке ключевых персон показывается только русское имя без оригинального имени в скобках и без подписи роли, например `Николас Кейдж и др.`. Поиск по бэклогу учитывает русское и оригинальное название, режиссёров, страны и всех ключевых персон. Карточка открывается кликом по названию фильма и также содержит ссылку RuTr. Увеличенные шрифт, межстрочный интервал и отступы делают таблицы удобнее для чтения, сохраняя горизонтальную прокрутку на узких экранах. Контурные кнопки лайка и дизлайка сразу переносят фильм в соответствующую колонку раздела «Просмотрено»; нейтральная кнопка корзины становится красной только при наведении и выполняет обратимое удаление. CalendarCheck в отдельной компактной колонке помечает фильм или альбом для ближайшего просмотра/прослушивания, подсвечивается золотистым цветом и позволяет вывести отмеченные позиции первыми; при оценке произведения отметка автоматически снимается. Длинные списки ключевых персон сокращаются до первой персоны и пометки «и др.», но в карточке доступны полностью.

«Актуализировать из TMDB» выбирает карточки без сохранённой полной TMDB-проверки, основных метаданных, IMDb/Кинопоиск rating, режиссёра или локального постера. Если отсутствуют TMDB-метаданные, IMDb или режиссёр, выполняется полное обогащение через TMDB и OMDb; Kinopoisk при этом вызывается только при отсутствующем КП-рейтинге, а постер загружается через TMDB Images. Если не хватает только КП-рейтинга, вызывается только Kinopoisk API. Если потерян только локальный файл постера, он повторно загружается с TMDB Images без обновления остальных данных. Полностью заполненные и уже проверенные карточки не создают внешних запросов.

В открытой карточке отдельная кнопка «Актуализировать из TMDB» применяет ту же логику только к выбранному фильму. В форме добавления эта кнопка выполняет полное первичное заполнение: TMDB нормализует названия, сведения и поле `Link` со ссылками TMDB/КП/RuTr, сохраняет `poster_path`, загружает постер `w185`, а ниже показывает рейтинги IMDb/КП, актёров, ключевых персон и описание. TMDB ID и заметки в форме не показываются. Кнопка «Очистить» полностью сбрасывает ручной ввод и найденные данные, оставляя модалку открытой. «Добавить в бэклог» сохраняет фильм в очередь, а контурные кнопки лайка и дизлайка сразу помещают его в соответствующий раздел просмотренного. Если после поиска изменить название или год и нажать актуализацию повторно, приложение выполняет новый поиск по изменённому полю, не используя ID предыдущего результата.

Форма альбома аналогично умеет найти и нормализовать запись по названию, исполнителю, году или MusicBrainz ID. В полной карточке доступны обложка, исполнители, первый выпуск, количество песен, типы релиза, жанры и теги, количество прослушиваний ListenBrainz, страна, лейбл, каталожный номер, штрихкод, формат носителя, статус конкретного издания и трек-лист. Альбом хранится как MusicBrainz `release-group`, а сведения конкретного издания берутся из выбранного официального `release`. Кнопка актуализации выбирает альбомы без исполнителя, локальной обложки или количества прослушиваний и для каждого выбранного альбома заново загружает полную карточку MusicBrainz/Cover Art Archive; ListenBrainz остаётся одним batch-запросом. Рейтинг MusicBrainz не используется и не хранится. В карточках фильма и альбома поле «Заметка» редактируется двойным кликом: потеря фокуса или `Ctrl/⌘ + Enter` сохраняет значение в библиотеке, `Escape` отменяет изменение.

Кнопки «✦ Подобрать похожее» и «↻ Новое от авторов» открывают одну модалку сразу в режиме LLM либо API соответственно; дополнительного переключателя внутри модалки нет. Чтобы не потерять введённый запрос или результат случайным кликом, эта модалка не закрывается нажатием на фон или клавишей Escape — закрыть её можно крестиком. В режиме LLM доступны минимальные рейтинги IMDb и Кинопоиска, диапазон лет, минимальная длительность, максимальное количество рекомендаций и свободный запрос. Каждое формальное условие можно отключить галочкой. IMDb по умолчанию ограничен значением 7, Кинопоиск также имеет значение 7, но изначально выключен, а максимальное количество рекомендаций равно 5. Условия передаются модели в системных инструкциях; после TMDB/OMDb/КП они проверяются повторно. Для Кинопоиска постпроверка мягкая: известная оценка ниже порога исключает фильм, но отсутствие КП-оценки не скрывает рекомендацию и отображается пустым значением. Перед отправкой приложение автоматически добавляет в системный контекст случайные выборки понравившихся фильмов и любимых актёров/режиссёров как мягкий сигнал, а также полный список уже добавленных фильмов, включая бэклог, просмотренное и корзину, как жёсткий список исключений. Максимумы для произведений и персон задаются раздельно в модалке; при каждом открытии они равны текущему количеству соответствующих записей в хранилище, то есть по умолчанию используется весь доступный контекст. Кнопка «Посмотреть промпт» показывает итоговый динамический контракт с фильтрами и контекстом до отправки модели. После ответа Codex рядом с результатами появляется кнопка «Сырой ответ модели», открывающая исходный JSON до обогащения и фильтрации. Колонки таблицы рекомендаций сортируются в обоих режимах.

Codex возвращает строго структурированный JSON: русское и оригинальное название, год и персональный комментарий. Сервер разбирает его, находит каждый фильм в TMDB, дополняет карточку сведениями TMDB/OMDb/Кинопоиска, повторно проверяет включённые фильтры и исключает дубли. В режиме API TMDB используются фильтры по актёрам, режиссёрам, IMDb/КП, голосам, диапазону лет, длительности и жанрам, а поле «Макс. фильмов» ограничивает размер результата. Верхняя граница года применяется до загрузки подробных карточек. Списки актёров и режиссёров при каждом открытии сброшены; без выбора хотя бы одной персоны запрос не запускается. IMDb и Кинопоиск включены со значением 7, а фильтр минимального количества голосов по умолчанию выключен. Английские и русские названия исключаемых жанров нормализуются, поэтому `Animation, Documentary` исключает в том числе локализованные жанры «мультфильм», «анимация» и «документальный». В обоих режимах основная таблица показывает прошедшие проверку карточки, а ниже раздел «Не прошли фильтрацию» повторяет отклонённые сущности отдельной таблицей. В режиме «Новое от авторов» записи вне выбранного диапазона лет не попадают в этот список, а сводка имеет вид «За период 2020–2026 найдено X фильмов, не прошли фильтрацию Y». Кнопка «Подробнее» справа открывает компактное окно со списком `название — причина`; это одинаково работает для фильмов и музыки. Уже находящиеся в библиотеке или корзине фильмы туда не попадают; любую другую отклонённую карточку можно вручную добавить в бэклог. Название открывает подробную карточку, кнопки «В бэклог», лайка и дизлайка сохраняют фильм, а серая кнопка «Убрать» удаляет строку только из текущей выдачи. Все действия над карточками — добавление, перенос, удаление из выдачи и восстановление — используют единый отклик на нажатие, защищены от повторного клика во время запроса и плавно скрывают карточку после успеха. В API-режиме колонка «Заметка» скрыта. Прогресс в обоих режимах показывает ключевые стадии поиска: запрос к LLM или выбранных персон, а затем обработку карточек. После загрузки итоговой таблицы выполненные индикаторы автоматически скрываются.

Для музыки та же модалка предлагает режимы LLM и MusicBrainz API. LLM получает отдельно ограничиваемые в форме случайные выборки понравившихся альбомов и любимых исполнителей, полный список уже добавленных и находящихся в корзине альбомов, диапазон лет и свободный запрос; по умолчанию оба максимума равны текущему количеству записей в хранилище, а структурированный результат независимо уточняется через MusicBrainz. Формальные фильтры можно отключать галочками, а итоговый промпт доступен до запуска. API-режим запрашивает у MusicBrainz до 100 release groups на каждого выбранного исполнителя, применяет год, типы, исключаемые фрагменты названия, дедупликацию и общий рейтинг кандидатов, после чего загружает полные карточки только для первых `Макс. альбомов`. По умолчанию исключены все специальные вторичные типы MusicBrainz: Compilation, Live, Remix, Soundtrack, DJ-mix, Audio drama, Audiobook, Demo, Field recording, Interview, Mixtape/Street и Spokenword, а также названия, содержащие `Deluxe` без учёта регистра. Оба списка исключений можно изменить или отключить. Поэтому значение 20 ограничивает дорогую детализацию и ListenBrainz двадцатью альбомами, но не discovery-ответ каждого исполнителя. Отфильтрованные альбомы также показываются с причинами в нижней таблице и доступны для ручного добавления в бэклог; уже имеющиеся в сервисе альбомы из неё исключены. Прогресс отдельно показывает запрос к LLM либо поиск по исполнителям, загрузку карточек MusicBrainz, обложек Cover Art Archive и статистики ListenBrainz; ошибки источников появляются в панели предупреждений сразу во время обработки, а после загрузки таблицы индикаторы скрываются. Выпадающие списки исполнителей, актёров и режиссёров содержат локальный поиск по имени, расширяются по ширине и высоте вместе с модалкой и закрываются кликом за их пределами или клавишей Escape. Без прокрутки показывается до 15 персон, последующие записи прокручиваются внутри списка. Все пользовательские ссылки альбомов, включая колонку `Link` рекомендаций, ведут на поиск в YouTube Music по названию, году и исполнителю.

Во время LLM- и API-рекомендаций доступна кнопка «Стоп». Прерывание кооперативное: текущий сетевой вызов завершается, следующие этапы и запросы не запускаются, а уже полностью обработанные карточки остаются в результирующей таблице. Такой же индикатор и кнопка доступны при массовой актуализации бэклога; после остановки интерфейс перечитывает библиотеку и показывает количество реально обновлённых карточек.

TMDB является обязательным источником для создания полной карточки: его ошибка показывается пользователю, а соответствующий фильм не добавляется в результаты. Кинопоиск — вспомогательный источник. При известном IMDb ID приложение сначала ищет точное соответствие по нему; если запрос завершился ошибкой или не дал результата, выполняется поиск по названию и году с нормализацией `ё → е`. При исчерпании лимита или другой ошибке обоих вариантов Kinopoisk API карточка всё равно создаётся по данным TMDB/OMDb, а интерфейс показывает предупреждение и оставляет КП-рейтинг и ссылку пустыми.

### Просмотрено

Фильмы разделены на три колонки:

- «Оценить» — реакция ещё не указана;
- «Понравилось»;
- «Не понравилось».

Повторное нажатие текущей контурной иконки лайка или дизлайка снимает реакцию и возвращает карточку в «Оценить». Любую карточку можно вернуть в бэклог. Карточки показывают русское и оригинальное название и постер справа; клик открывает подробные данные. Звёздочка независимо добавляет фильм в избранное и не меняет реакцию, статус или другие атрибуты.

Для музыки используются те же три колонки и механика реакций. Справа в карточке прослушанного альбома показывается его обложка. Звезда независимо добавляет альбом в музыкальное избранное. Кнопки добавления на вкладке «Просмотрено» нет ни для одного типа контента.

### Избранное

Переключатель позволяет открыть режим фильмов или музыки. Вкладка показывает отмеченные звёздочкой фильмы или альбомы: карточка открывает полную информацию, а повторное нажатие звезды убирает объект только из избранного. Маркер сохраняется независимо от перемещений между бэклогом и просмотренным/прослушанным. Отдельного поля поиска на вкладке нет.

### Персоны

Две таблицы содержат любимых режиссёров и актёров: компактное фото профиля, русское и оригинальное имя; TMDB ID скрыт из таблиц и остаётся в карточке. Под портретом показывается ссылка IMDb, если у персоны есть IMDb ID. Внешний ID получается вместе с англоязычной карточкой TMDB через `append_to_response=external_ids`, без дополнительного HTTP-запроса, и сохраняется в `details_json`. TMDB-фото размера `w185` загружается и локально кешируется при рекомендации, ручном поиске и обновлении. Все видимые колонки сортируются нажатием на заголовок; по умолчанию актёры и режиссёры отсортированы по русскому имени, исполнители — по имени MusicBrainz. Персону можно добавить вручную или сначала найти и нормализовать через TMDB прямо в форме добавления; первоначально введённые значения сохраняются как `Raw`. Клик по строке открывает карточку, из которой можно полностью актуализировать только выбранную персону через англоязычную и русскую карточки TMDB и TMDB Images. Пункт `… → ⟳ Обновить` обращается к тем же источникам для персон без TMDB ID, IMDb ID, ещё не сверенных персон и карточек с известным профилем, у которых отсутствует локальный файл. Рядом находится кнопка «✦ Рекомендовать похожее»: в LLM-модалке можно переключиться между режиссёрами и актёрами, задать свободный запрос, максимальное количество результатов и максимальное количество любимых персон выбранной роли в контексте. По умолчанию лимит контекста равен числу активных режиссёров или актёров; полный список выбранной роли, включая корзину, остаётся жёстким исключением повторов. Ответ Codex уточняется через TMDB, после чего персону можно добавить из таблицы вместе со ссылкой IMDb под портретом. В результатах рекомендаций клик по доступной фотографии актёра, режиссёра или исполнителя открывает её в отдельном увеличенном просмотре. Контурная кнопка корзины нейтральна в обычном состоянии и становится красной при наведении; она скрывает выбранную роль персоны из активного списка.

В режиме «Музыка» здесь показываются исполнители и группы с типом, страной и фотографией; MusicBrainz ID остаётся внутри карточки. Из уже полученного MBID без дополнительного API-вызова строится ссылка `https://musicbrainz.org/artist/{MBID}`, которая показывается под портретом исполнителя в рекомендациях, списке персон и подробной карточке. При рекомендации, добавлении или актуализации исполнителя приложение запрашивает квадратный `artistthumb` через fanart.tv по существующему MBID, выбирает наиболее популярный вариант и локально уменьшает его системной утилитой macOS `sips` до 200 px перед сохранением в `data/artwork/people`; исходный URL и локальный путь хранятся в SQLite. Отсутствие изображения или временная ошибка fanart.tv не блокирует сохранение исполнителя. Исполнителей можно добавить, найти, точечно актуализировать и обратимо переместить в корзину. Пункт `… → ⟳ Обновить` также выбирает исполнителей без локальной фотографии. Кнопка «✦ Рекомендовать похожее» открывает LLM-only флоу с лимитом результатов (по умолчанию 5): модели передаются свободный запрос и полный список уже добавленных исполнителей, включая корзину. После ответа модели прогресс отдельно показывает получение карточек через MusicBrainz и загрузку фотографий через fanart.tv.

### Корзина

Переключатель разделяет корзину на фильмы с персонами и альбомы с исполнителями; для каждого режима таблицы и счётчики строятся отдельно. Объекты восстанавливаются одной кнопкой. Обычное перемещение в корзину мягкое: основные записи и связи не уничтожаются, а содержимое учитывается при дедупликации рекомендаций. Кнопка «Очистить всю корзину» после подтверждения безвозвратно удаляет все объекты из SQLite и удаляет их локальные постеры и обложки из `data/artwork`, если эти файлы больше не используются другими записями.

## SQLite

Активная база: `data/library.sqlite3`. Описание таблиц и `awards_json`: `data/SCHEMA.md`.

SQLite хранит URL источника и относительный путь к локальному файлу обложки, постера, TMDB-профиля или fanart.tv-портрета. JPEG находятся в `data/artwork/albums/`, `data/artwork/movies/` и `data/artwork/people/`; весь `data/artwork/` исключён из Git. При отсутствии файла локальный HTTP endpoint повторно загружает его из Cover Art Archive, TMDB Images или уже сохранённого URL fanart.tv и обновляет путь в базе.

Заполнить отсутствующие файлы локального кэша фильмов, альбомов, TMDB-профилей и музыкальных исполнителей можно командой `python3 scripts/cache_artwork.py`. Только фотографии исполнителей загружает `python3 scripts/cache_artwork.py --kind artists`. Чтобы атомарно заменить уже сохранённые крупные изображения новыми `w185`/`front-250`/fanart 200 px, явно запустите `python3 scripts/cache_artwork.py --refresh-existing`; без этого флага существующие файлы не перезаписываются.

Главные таблицы:

- `content_types`, `content_items`, `movies`, `albums` (включая `raw_json` с первоначальным вводом);
- `people`, `interest_roles`, `movie_people` (включая `raw_json`, метаданные и время последней сверки персон);
- `music_artists`, `album_artists` — исполнители MusicBrainz и связи с альбомами;
- `genres`, `movie_genres`;
- `content_aliases`;
- `trash_entries` — маркеры обратимого удаления со снимком названия для экрана корзины.
- `favorite_movies` — legacy-таблица независимых отметок избранных фильмов и альбомов.

Первичная SQLite-база построена из сохранённых CSV:

```bash
python3 scripts/migrate_csv_to_sqlite.py --force
```

`--force` полностью пересоздаёт активную БД из `legacy/csv/` и удаляет изменения, сделанные после миграции.

Первичное наполнение музыки использует список из `legacy/csv/interests.csv`, скопированный в `data/music_seed_artists.json`, поэтому приложение во время работы не зависит от `legacy/`. Скрипт находит 46 исполнителей и только полноценные альбомы выбранного года: `primary-type = Album` и пустой список `secondary-types` (без Live, Remix, Compilation, Soundtrack и других специальных версий). Он делает реальные запросы с лимитом 1 запрос/с и изменяет выбранную базу, поэтому требует явного подтверждения:

```bash
python3 scripts/bootstrap_music.py --database data/library.sqlite3 --year-from 2026 --year-to 2026 --archive-out-of-scope --apply
```

Без `--apply` команда ничего не меняет. `--archive-out-of-scope` обратимо перемещает ранее загруженные альбомы других лет и специальных типов в корзину. Для безопасной проверки укажите путь к временной базе.

## MusicBrainz

Ключ и OAuth не нужны. Все обращения передают `User-Agent: WhatsNewChecker/2.0 (gavrevns@gmail.com)` и проходят через общий ограничитель не чаще одного запроса в 1,05 секунды. Временные ответы 429/503 и сетевые сбои повторяются ограниченное число раз; массовые операции продолжают работу с остальными записями и возвращают предупреждение в интерфейс.

Вместе с карточкой release group приложение проверяет Cover Art Archive. При наличии фронтальной обложки в SQLite сохраняются URL `https://coverartarchive.org/release-group/{release_group_mbid}/front-250` и относительный путь к локальному JPEG. Для фильмов TMDB Images аналогично используется постер `w185`, а квадратный `artistthumb` fanart.tv локально уменьшается до 200 px. Эти размеры превышают фактический размер иконок в интерфейсе, но заметно уменьшают локальный кэш относительно исходных изображений. Если изображение отсутствует, сохраняется пустое поле; временная ошибка вспомогательного сервиса не стирает уже известный файл. Документация: [TMDB Image Basics](https://developer.themoviedb.org/docs/image-basics), [Web Service API](https://musicbrainz.org/doc/MusicBrainz_API), [Cover Art Archive API](https://musicbrainz.org/doc/Cover_Art_Archive/API), [fanart.tv API v3.2](https://api.fanart.tv/) и [Music Artist Thumb](https://wiki.fanart.tv/ImageTypes/Music/artistthumb/).

ListenBrainz вызывается через `POST /1/popularity/release-group`. Идентификаторы разбиваются на пачки до 10 записей, каждый запрос выполняется только один раз с таймаутом 15 секунд. В рекомендациях сбой одной пачки не скрывает альбомы: у соответствующих карточек остаётся пустое количество прослушиваний, предупреждение сразу появляется в интерфейсе, а обработка продолжается. В SQLite сохраняются `total_listen_count` и время успешной проверки; `null` означает, что ListenBrainz пока не располагает данными. После изменения Popularity API в июле 2026 приложение поддерживает заголовок `Authorization: Token ...` из `LISTENBRAINZ_USER_TOKEN`; без токена сохраняется совместимый публичный вызов, а HTTP 401 превращается в понятное предупреждение. Массовая музыкальная актуализация касается только альбомов без локальной обложки, исполнителя или количества прослушиваний; для каждой выбранной карточки заново загружается полный набор MusicBrainz-данных. Документация: [ListenBrainz Popularity API](https://listenbrainz.readthedocs.io/en/latest/users/api/popularity.html).

## API-ключи

Для локального запуска через `.app` скопируйте безопасный шаблон:

```bash
cp SECRETS.example SECRETS
```

Заполните локальный файл `SECRETS`:

```python
TMDB_API_KEY = "..."
OMDB_API_KEY = "..."
KINOPOISK_API_KEY = "..."
FANART_PROJECT_KEY = "..."  # project key из fanart.tv/get-an-api-key
LISTENBRAINZ_USER_TOKEN = "..."  # токен из listenbrainz.org/settings
CODEX_RECOMMENDATION_MODEL = "gpt-5.6-terra"
```

`SECRETS` добавлен в `.gitignore`; в Git включается только `SECRETS.example` с пустыми значениями. Приложение читает файл без выполнения его как Python-кода.

Переменные окружения имеют приоритет над `SECRETS`:

```bash
export TMDB_API_KEY="ваш_tmdb_ключ"
export OMDB_API_KEY="ваш_omdb_ключ"
export KINOPOISK_API_KEY="ваш_kinopoisk_ключ"
export FANART_PROJECT_KEY="ваш_fanart_project_key"
export LISTENBRAINZ_USER_TOKEN="ваш_listenbrainz_token"
python3 app/server.py --open-browser
```

Не храните реальные ключи в notebook, исходном коде или отслеживаемых конфигурационных файлах. Если ключ уже попадал в Git или был опубликован, одного добавления в `.gitignore` недостаточно — ключ необходимо перевыпустить.

TMDB не предоставляет структурированные награды кинофестивалей. Поле `awards_json` не затирается пустым ответом и допускает подключение будущего источника Cannes/Berlinale/Venice без миграции схемы.

## Codex SDK и подписка ChatGPT

LLM-рекомендации запускаются через официальный `openai-codex` в изолированном временном каталоге, с read-only sandbox и запретом подтверждений. SDK использует локальную авторизацию Codex, общую для CLI и IDE extension. При входе через ChatGPT расходуется доступ, включённый в план ChatGPT; `OPENAI_API_KEY` приложению не нужен. Обычный OpenAI Platform API имеет отдельный usage-based биллинг и в этой функции не используется. Ответ ограничен JSON Schema из `app/movie_recommendations.schema.json`, `app/album_recommendations.schema.json` или `app/person_recommendations.schema.json`; затем приложение выполняет независимое обогащение через TMDB/OMDb/Кинопоиск либо MusicBrainz.

Модель по умолчанию — `gpt-5.6-terra`. Её можно изменить через `CODEX_RECOMMENDATION_MODEL` в локальном `SECRETS` или одноимённую переменную окружения.
